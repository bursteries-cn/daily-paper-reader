## 摘要
大型语言模型（LLM）在代码生成、库推荐和依赖配置等软件工程任务中展现出强大能力。然而，最近研究表明，LLM可能遭受包幻觉问题，即生成不存在或无效的包名。攻击者可能利用这些幻觉名称注册恶意包，从而发起软件供应链攻击。因此，缓解包幻觉对于提高LLM辅助软件开发的可靠性和安全性至关重要。本文提出了BOUND，一个轻量级的局部模型编辑框架，用于缓解LLM中的包幻觉。BOUND将包幻觉缓解问题建模为包有效性边界编辑问题，其中边界指模型在给定任务上下文中区分有效包与幻觉包名的能力。它首先通过风险感知定位策略定位与包幻觉相关的模块，然后使用轻量级LoRA适配器编辑这些模块，采用边界感知目标，增强有效包、抑制幻觉包并保持局部行为。实验结果表明，BOUND在有效减少包幻觉的同时保留了有效包推荐。在包推荐任务中，BOUND在编辑提示上将包级幻觉率（Package-HR）降低了79.9%，在未见提示上降低了65.4%。学习到的包有效性边界进一步泛化到其他与包相关的任务，在代码生成中降低了12.8%的Package-HR，在pip install推荐中降低了34.0%。这些结果表明，BOUND优化了LLM的包有效性边界，提高了包相关输出的可靠性。

## Abstract
Large language models (LLMs) have demonstrated strong capabilities in software engineering tasks, such as code generation, library recommendation, and dependency configuration. However, recent studies show that LLMs may suffer from package hallucination, where they generate non-existent or invalid package names. These hallucinations can be exploited in software supply chain attacks, as attackers may register malicious packages under hallucinated names. Therefore, mitigating package hallucination is important for improving the reliability and security of LLM-assisted software development. In this paper, we introduce BOUND, a lightweight localized model editing framework for mitigating package hallucinations in LLMs. BOUND formulates package hallucination mitigation as a package-validity boundary editing problem, where the boundary refers to the model's ability to distinguish valid packages from hallucinated package names under a given task context. It first locates modules related to package hallucination through a risk-aware localization strategy, and then edits these modules with lightweight LoRA adapters using a boundary-aware objective that reinforces valid packages, suppresses hallucinated packages, and preserves locality behavior. Experimental results show that BOUND effectively reduces package hallucinations while preserving valid package recommendations. In the package recommendation task, BOUND reduces package-level hallucination rate (Package-HR) by 79.9% on edit prompts and by 65.4% on unseen prompts. The learned package-validity boundary further generalizes to other package-related tasks, reducing Package-HR by 12.8% in code generation and by 34.0% in pip install recommendation. These results show that BOUND refines the package-validity boundary of LLMs and improves the reliability of package-related outputs.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：大型语言模型（LLM）在代码生成、库推荐、依赖配置等软件工程任务中被广泛使用。然而，LLM 可能产生**包幻觉（package hallucination）**，即生成不存在或无效的软件包名称。攻击者可注册这些幻觉名称的恶意包，引发**软件供应链攻击**（如包混淆攻击）。现有缓解方法（外部检索、自校正、全参数微调）存在推理开销大、可能抑制输出、或成本高且损害通用能力等问题。
- **核心问题**：如何在不大量修改模型参数的前提下，让 LLM 学会区分有效包与幻觉包，精炼“包有效性边界”。
- **整体含义**：首次将包幻觉缓解形式化为**包有效性边界编辑问题**，并通过轻量级局部模型编辑实现，对提升 LLM 辅助开发的可靠性和安全性有重要意义。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
将包幻觉视为模型在给定任务上下文下区分有效/无效包的边界错误，而非简单的知识错误。通过定位与包幻觉最相关的模块，注入轻量级 LoRA 适配器，并优化边界感知目标来精炼该边界。

### 关键技术细节（BOUND 框架）

1. **高风险提示集构建**  
   - 提取原始提示，对每个提示生成 5 次回答，提取包名，用 PyPI 元数据（带知识截止日期）判断有效性。  
   - 计算样本级幻觉率（Sample-HR），保留 >0.5 的提示作为高风险提示，用于后续定位和编辑。

2. **关键模块定位（Risk-aware Localization）**  
   - 候选模块：所有解码层的注意力投影（Q/K/V/O）和 MLP 投影（gate/up/down）。  
   - 对每个编辑案例，计算**边界风险分数**：  
     `R_i = LSE(logits[幻觉令牌]) - λ_a·LSE(logits[有效令牌])`  
   - 反向传播该损失，计算每个候选模块的**显著性分数**：  
     `s_i(m) = Mean(|∇W_m R_i ⊙ W_m|)`  
   - 对所有编辑案例求平均，选择 top-k 模块作为定位集合。

3. **边界感知模型编辑（Boundary-aware Model Editing）**  
   - 在定位模块上注入 LoRA 适配器（rank=8，alpha=16，dropout=0.05），基础权重冻结。  
   - **优化目标（三部分）**：  
     - **有效包负对数似然（Valid NLL）**：增强有效包生成。  
     - **幻觉包非似然（Hallucinated Unlikelihood）**：抑制幻觉包概率。  
     - **局部性 KL 散度（Locality KL）**：保持对原始提示和有效包相关提示的输出分布不变。  
   - 总损失：`L_BOUND = λ_v·L_valid + λ_h·L_hall + λ_l·L_loc`（默认 λ_v=1.0，λ_h=0.15，λ_l=0.03）。  
   - 训练 3 个 epoch，batch size=1，学习率 2e-4。

### 算法流程（文字描述）
1. 输入：高风险提示集，冻结的基座模型。  
2. 定位阶段：对每个案例前向传播 => 计算边界风险分数 => 反向传播 => 计算模块显著性 => 聚合选 top-5。  
3. 编辑阶段：在定位模块注入 LoRA => 对每个编辑案例循环前向传播计算三个损失 => 仅更新 LoRA 参数 => 得到编辑后的模型。

## 3. 实验设计：数据集、基准、对比方法

### 数据集
- **来源**：采用 Spracklen et al. [12] 的 LLM 生成提示数据集（Python 子集），源自流行 Python 包描述。  
- **构建**：对每个模型（DeepSeekCoder-6.7B, Qwen3-8B, Llama-3.1-8B）分别筛选高风险提示（Sample-HR>0.5），得到 741、609、1134 个高风险提示。  
- **划分**：每个模型随机抽 4×50 个提示作为编辑集，其余作为未见评估集。

### 评估场景
- **主要任务**：包推荐（package recommendation）。  
- **泛化任务**：代码生成（提取 import 语句映射到 PyPI 包名）、pip install 推荐。

### 对比方法（5 个基线）
| 方法 | 类型 |

| Full-FT [12] | 全参数微调（监督学习） |

| MEMIT [36] | 批量事实编辑 |
| DINM [28] | 行为编辑（去毒化） |

### 评估指标
- **Sample-HR**：生成回答中包含至少一个幻觉包的样本比例（越低越好）。  
- **Package-HR**：幻觉包在所有提取包中的比例（越低越好）。  
- **Valid-Rate**：至少包含一个有效包的样本比例（越高越好，反映是否过度抑制输出）。

### 公平性控制
- 所有可训练基线使用相同的编辑案例（4×50）。  
- 每个方法报告 4 折编辑的平均结果。  
- 生成设置统一：temperature=0.7，top_p=0.9，每个提示采样 5 次。

## 7. 优点

- **问题重新定义**：将包幻觉从知识错误重新定义为边界编辑问题，更贴近实际现象（模型能推荐部分有效包，但无法区分似幻包）。  
- **轻量级编辑**：仅编辑少量模块（top-5）和极少参数（LoRA），避免了全参数微调的高成本和灾难性遗忘。  
- **多任务泛化**：编辑仅基于包推荐，却能提升代码生成和 pip install 中的包名准确性，表明学到了可迁移的包有效性边界。  
- **精心设计的损失函数**：三部分损失互相补充，既抑制幻觉又保留有效输出且维持局部稳定，消融验证了每个分量的贡献。  
- **充分的消融和公平对比**：对每个基线使用相同编辑案例，报告四折平均，控制随机因素。
