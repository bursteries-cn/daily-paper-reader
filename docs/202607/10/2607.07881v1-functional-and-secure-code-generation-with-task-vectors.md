## 摘要
大型语言模型（LLM）越来越多地被用于代码生成，但它们难以生成既功能完整又无安全漏洞的代码。先前提升此类代码生成LLM安全代码生成能力的研究主要侧重于使用不同数据集分别评估代码功能性和安全性，或专注于生成后查找漏洞。与此同时，文本生成领域在对齐技术方面取得了显著进展，其中模型被调整以使其输出表现出某些特质（例如，有帮助性、无害性）。特别值得关注的是任务向量算术，其中对LLM权重的线性操作可用于任意增强对齐，同时仅产生最小的计算开销。我们开发了一种新方法SecVecCoder，利用任务向量生成可信代码，该代码同时具备功能性和安全性，无需生成后调整。在CodeGuard+基准测试上针对来自三个系列的六个代码生成LLM，SecVecCoder将可信代码补全率比基础模型提高了2.1至36.0个百分点，对未见过的CWE类型的改进高达39.1个百分点。由于代码生成LLM的有效性仅依赖于改变模型权重，SecVecCoder不需要特定于方法的解码，因此其解码延迟平均在基础模型的0.6%以内。

## Abstract
Large language models (LLMs) are increasingly used for code generation, but they struggle to generate functional code free of security vulnerabilities. Prior work to improve the secure code generation abilities of such coding LLMs has largely focused on evaluating code functionality and security separately using different datasets, or focused on finding vulnerabilities post-generation. At the same time, the text-generation domain has seen significant work on alignment techniques, where models are tuned such that their outputs exhibit certain qualities (e.g., helpfulness, harmlessness). Of particular interest is task-vector arithmetic, where linear operations on LLM weights can be used to arbitrarily enhance alignment while incurring only minimal computational overhead. We develop a novel method, SecVecCoder, leveraging task vectors to produce trustworthy code that is simultaneously functional and secure without the need for post-generation adjustment. Across six coding LLMs from three families on the CodeGuard+ benchmark, SecVecCoder improves the rate of trustworthy code completions by 2.1-36.0 percentage points over the base model, with improvements on unseen CWE types reaching up to 39.1 percentage points. Since the effectiveness of the coding LLM relies only on changing the model weights, SecVecCoder requires no method-specific decoding and hence achieves a decoding latency within 0.6% of the base model's, on average.

## 1. 核心问题与整体含义（研究动机和背景）

大型语言模型（LLM）在代码生成方面展现出了卓越的能力，并被广泛用作编码助手。然而，这些模型通常是在包含大量来自互联网的代码语料上训练的，其中可能含有安全漏洞。已有研究表明，AI编码助手倾向于生成存在可利用弱点的代码，并且可能导致开发人员对生成代码的安全性产生过度自信，从而引入更多漏洞。

当前改进安全代码生成的方法主要有三类：
- **训练时方法**：通过微调或适配器修改模型权重，但往往需要大量训练数据和计算资源。
- **生成后方法**：在生成后使用漏洞检测和自动修复，但会引入显著的计算开销。
- **推理时方法**：通过约束解码或辅助模块在生成过程中施加安全性，但会增加推理延迟。

现有工作大多将功能性和安全性分开评估（使用不同数据集），或者只关注单一维度。然而，可信代码生成必须**同时**保证代码的功能正确性和安全性。因此，亟需一种既能兼顾两者，又能在训练和推理中保持高效的方法。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
本文提出 **SecVecCoder**，利用**任务向量算术（task-vector arithmetic）** 对LLM权重进行线性操作，以引导模型生成同时具备功能性和安全性的代码。任务向量定义为微调后模型与基础模型权重的差值，通过简单的加减运算即可增强或抑制特定行为。

### 关键技术细节
1. **任务向量构造**：
   - 从基础模型 $W_{\text{base}}$ 出发，分别用安全代码和易受攻击代码微调得到 $W_{\text{sec}}$ 和 $W_{\text{vul}}$。
   - 定义安全任务向量 $\tau_{\text{sec}} = W_{\text{sec}} - W_{\text{base}}$，不安全任务向量 $\tau_{\text{insec}} = W_{\text{vul}} - W_{\text{base}}$。

2. **任务向量算术操作（三种对比）**：
   - **否定（Negation）**：$W_{\text{steered}} = W_{\text{base}} - \theta \tau_{\text{insec}}$，仅抑制不安全行为。
   - **对比（Contrast）**：$W_{\text{steered}} = W_{\text{base}} + \theta (\tau_{\text{sec}} - \tau_{\text{insec}})$，沿安全与不安全差异方向移动。
   - **安全锚定（Secure-Anchored，本文采用）**：$W_{\text{steered}} = W_{\text{base}} + \tau_{\text{sec}} - \theta \tau_{\text{insec}}$，先锚定到安全微调点，再抑制不安全方向。

   其中 $\theta$ 为控制强度的缩放系数。

3. **微调策略选择**：比较了SFT、SafeCoder-style和**LPO（Localized Preference Optimization）**三种微调方法。通过计算安全/不安全任务向量的余弦相似度和符号一致性，发现LPO能将两个向量显著区分（负相关），从而更适合任务向量算术。因此SecVecCoder采用LPO微调。

4. **LPO微调细节**：
   - 使用成对的安全/不安全代码补全数据，利用token级差异掩码聚焦于区分性token。
   - 损失函数包括偏好损失和共享token的负对数似然正则化。

5. **推理**：SecVecCoder仅修改模型权重一次，生成时采用标准自回归解码，无额外开销。

## 6. 主要结论与发现

1. LPO微调能产生高度可分的任务向量（安全/不安全向量负相关），是任务向量算术的最佳基础。
2. **安全锚定+θ=1.5**组合在六个模型上平均主CWE sec-pass@1最高（78.9%），相对基础模型提升36.1%。
3. 在五个模型上，SecVecCoder主CWE sec-pass@1超越所有现有方法，提升3.8%~27.5%（DeepSeek-6.7B例外）。
4. 未见CWE场景下，SecVecCoder的sec-pass@1绝对提升2.0~39.1个百分点，泛化能力强。
5. 训练成本仅为SafeCoder的8.0%~12.5%，推理延迟几乎不变（平均0.6%）。
6. 消融实验表明同时使用安全和不安全任务向量是必要的，去除任一项都会显著下降。
