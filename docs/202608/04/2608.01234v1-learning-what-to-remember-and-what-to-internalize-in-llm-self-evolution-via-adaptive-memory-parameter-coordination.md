## 摘要
大语言模型智能体日益在动态环境中运行，其中工具接口、API和用户需求在部署后发生变化。现有的自我进化方法主要遵循两种范式：基于外部装备的方法，将反馈外部化为可编辑的记忆或技能以实现快速适应；以及基于参数的方法，将经验内化为模型参数以实现更深层次的能力提升。然而，单独使用任何一种机制都会在灵活性和性能之间产生权衡。本文探讨智能体如何协调两个通道以实现稳健的自我进化。我们提出了COVE，一个统一的智能体自我进化框架，通过任务感知路由、阶段感知调度和知识优化，将基于外部装备的学习和基于参数的学习相结合。通过这种设计，COVE将自我进化视为一个协调过程，而非对经验的 indiscriminate 积累，它根据任务和知识类型匹配适当的学习机制。跨多个任务类别的实验表明，COVE优于单通道进化策略，在变化环境下展现出更稳健和高效的改进。

## Abstract
Large language model agents increasingly operate in dynamic environments where tool interfaces, APIs, and user requirements change after deployment. Existing self-evolution methods mainly follow two paradigms: harness-based approaches, which externalize feedback into editable memories or skills for rapid adaptation, and parameter-based approaches, which internalize experience into model parameters for deeper capability improvement. However, using either mechanism alone creates a trade-off between flexibility and performance. This paper asks how an agent can coordinate both channels to achieve robust self-evolution. We present COVE, a unified agent self-evolution framework that combines harness-based and parameter-based learning through task-aware routing, stage-aware scheduling, and knowledge optimization. Through this design, COVE treats self-evolution not as indiscriminate accumulation of experience, but as a coordinated process that matches tasks and knowledge types to appropriate learning mechanisms. Experiments across multiple task categories show that COVE outperforms single-channel evolution strategies, demonstrating more robust and efficient improvement under changing environments.

### 2. 论文提出的方法论

#### 2.1 核心思想

COVE 的核心思想是：**不同的任务暴露不同类型的学习结构，不同的知识具有不同的易变属性，因此自我进化应在任务维度上选择正确的通道（route），在时间维度上选择合适的时机（schedule），在知识维度上决定知识的存放位置（where to store）**。COVE 将"进化"从单一的整体操作分解为三个可学习的决策：

- **走哪个通道**（任务感知路由）
- **什么时候切换通道**（阶段感知调度）
- **知识应该驻留在哪里**（双模态知识优化）

#### 2.2 任务形式化

COVE 将智能体建模为：参数化策略模型 π_θ、外部知识库 K = {k_j}、执行环境 E。智能体面对顺序任务流 {τ_i}。环境返回反馈 f_i（包含奖励、成败标签、错误追踪、工具调用日志等）。支持两类更新：

- 装备侧更新：`K ← U_h(K, τ_i, f_i)`——从反馈提取可复用记忆/技能条目并更新知识库。
- 参数侧更新：`θ ← U_θ(θ, D_train, K)`——用累积轨迹和知识增强训练数据优化参数。

优化目标不是最大化 K 的大小，而是在推理时间和训练时间预算约束下最大化累计任务效用：

```
max Σ R_i − α Σ C_tok_i − β Σ C_train_m
```

其中 R_i 为任务奖励，C_tok_i 为提示词 token 成本，C_train_m 为第 m 次参数更新的计算成本。

#### 2.3 任务感知路由（Task-aware Routing）

- **动机**：对所有任务同时使用两种通道既不经济也不稳健。
- **实现**：路由器被实例化为一个**反馈条件化的决策策略**（而非手工评分函数）。给定任务描述 τ_i 与执行反馈 f_i（包含结果状态、标量分数、评估器的诊断消息），路由器查询一个受约束的判卷器（constrained judge），返回结构化决策记录 d_i = (m_i, s_i, r_i)，其中：
  - m_i 为所选进化通道；
  - s_i 为一组简短的自由形式描述符（如 dynamic_tool、logical_rigor），刻画任务行为的原因；
  - r_i 为一句理由说明。
- **三通道选项** M = {harness_only, parametric_candidate, hybrid}：
  - **harness_only**：失败源于易变或上下文相关的知识，不适合权重更新；
  - **parametric_candidate**：任务奖励可内化的能力，难以用提示词表达；
  - **hybrid**：任务同时表现出两种信号（如既需要形式推理又需要工具/检索交互）。

#### 2.4 阶段感知调度（Stage-aware Scheduling）

- **动机**：装备与参数两类通道存在阶段依赖的权衡——装备进化快但可能早期饱和，参数进化更深层但计算代价高。
- **核心设计**：COVE 不固定两个通道的顺序或频率，而是引入**阶段感知进化触发器（Stage-aware Evolution Trigger）**，基于三个可复现条件动态决定是否触发参数更新：
  1. **性能平台期（Plateau）**：最近 w 个回合的成功率或平均奖励提升低于阈值 ε；
  2. **数据充分性（DataSufficient）**：高质量轨迹数量 |D_q| ≥ N；
  3. **冷启动失败（ColdStartFailure）**：某一任务族前 k 个任务的成功率低于阈值 τ_c，表明装备侧进化无法自举。
- **触发逻辑**：`Trigger = Plateau ∨ DataSufficient ∨ ColdStartFailure`
  - 前两个条件支持常见路径：装备先探索 → 参数后内化；
  - 第三个条件支持反向路径：先用参数更新建立最低能力底线，再启用装备侧进化（如 Lean 定理证明场景）。

#### 2.5 KnowledgePO：双模态知识优化

这是 COVE 中决定**通道之间如何交换知识**的核心机制，目标是让装备侧和参数侧形成闭环：外部记忆提升训练 rollout 质量，训练后的参数在知识稳定后减少对外部记忆的依赖。

**（1）装备辅助参数侧：记忆感知 rollout（Memory-aware Rollout）**

- 每条知识条目 k_j 在创建时被赋予**易变标签** ℓ_j ∈ L = {volatile, stable, strategic}（易变、稳定、策略性）：
  - **易变知识**：依赖外部表面形式（如 API 名称、表结构），应留在 Memory 中，在训练中明确防止被内化；
  - **稳定知识**：捕捉深层的持久模式（如算法惯用语、领域推理例程），适合参数内化；
  - **策略性知识**：更高层的启发式（如调试计划），应留在 Memory，仅在重复证据表明其稳定后才内化。
- 非一次性标注：当初始非易变条目被反复修订时，系统将其**提升为易变**（repeated correction 被视为依赖变动外部状态的证据）。
- 易变条目在检索和 rollout 收集时用显式标记包裹，如 `<volatile>...</volatile>`。
- rollout 时检索 top-k 相关记忆/技能注入消息列表，提升 rollout 成功率和轨迹质量。

**（2）反背诵奖励（Anti-Recitation Reward）**

- 针对易变条目的专门机制：训练前将易变条目中的名称**随机重命名**。当前回合的合法易变名称仅限当前检索记忆中的 N_i（而非历史上出现过的任何名称）。
- 如果模型调用了**过时或未观察到的易变名称**，说明它依赖记忆化而非检索条件执行，将受到惩罚：

```
R = R_task − λ · I[uses stale or unobserved volatile name]
```

- 稳定知识不受此惩罚，允许可复用模式被内化到模型权重中。目标是让模型学会"读取当前条目并据此行动"而非"记住并重复"。

**（3）参数辅助装备侧：记忆释放（Memory Release）**

- 累积记忆会消耗上下文并增加检索噪声，因此训练后对稳定记忆运行 **A/B 评估**：条件 A 将 k_j 包含在检索上下文中，条件 B 移除它。若移除后性能下降 Δ_j 低于阈值（且该条目前曾在训练前有正向效用），则将其标记为"已内化"并从在线检索中释放（保留在存档库供审计）。
- **易变记忆永不释放**——它们的价值恰恰在于携带当前外部符号。这一设计保持知识库紧凑，同时不丢失必须外部化的知识。

#### 2.6 算法流程概述

COVE 工作流（Algorithm 1）概括如下：

1. 对每个任务 τ_i：检索记忆 → 装备侧推理 → 收集反馈 → 提取候选条目并打标签 → 更新知识库（插入/合并/修订/丢弃）→ 将反复修订的条目提升为 volatile；
2. 路由决策（Route）选择通道；
3. 若未触发 Trigger，则继续装备侧探索；
4. 若路由为 parametric_candidate 或 hybrid，则触发参数更新（promoted by Trigger）；
5. 训练时注入记忆条目、应用任务奖励与反背诵惩罚；
6. 评估稳定记忆，决定释放（internalized）、丢弃（无效用）或保留；
7. 用更新后的策略和知识库恢复装备侧交互。

### 6. 论文的主要结论与发现

1. **单一通道均不充分**：装备侧进化对 Lean 定理证明几乎无提升（知识积累 50→250 回合成功率持平；检索 2→8 条记忆增长率 <3%）；参数侧进化在 API 重命名后从 40.5% 降至 16.5% 成功率，API 调用正确率从 96.5% 降至 54.0%。
2. **任务与知识结构决定通道选择**：任务层面存在互补瓶颈——易变任务需要可编辑的装备侧适应，能力受限任务需要参数侧学习。知识层面，**易变性（volatility）是决定外部化还是内化的关键判据**：高频率的接口知识内化后极其脆弱（59.3% 成功率下降），而稳定的推理模式适合内化。
3. **内任务时序也很关键**：阶段对齐比较表明，平台期触发的参数更新优于始终开启的持续训练和仅装备进化。
4. **COVE 的主结果**：在 Lean4、APPS、HotpotQA、MATH 上取得最优，在 TableQA 上保持竞争力；与 indiscriminate 参数学习相比，训练 token 减少 86%（宏平均）。在 router 判定为 hybrid 的子集上，COVE 获得最高成功率（24.1%，基线 15.6%，最强单通道 21.3%）。
5. **路由有效**：COVE 的路由器只用 Always-Both 的 16% 参数 token 成本，达到 65.0 的平均性能（Always-Both 为 69.0），效率（Eff.）为 28.83，远超 Random-Route（8.82）和 Always-Both（4.89）。
6. **抗背诵机制有效**：在 API 重命名场景下，抗背诵模型保持稳定的 API 正确率（92.5% vs 54.0%），且性能下降主要转为"API 正确但答案错误"（任务推理阶段问题）而非"API 错误"（接口选择阶段问题）。注意力分析显示抗背诵模型更关注 `<volatile>` 标记和当前指令区域。
7. **总体结论**：有效的自我进化需要协调双通道，将反馈视为异质知识，其存储和更新机制应匹配知识的稳定性与复用模式。

### 7. 优点

1. **问题定义清晰且具有实际意义**：将"灵活性与性能的权衡"这一工程痛点转化为可操作的科研问题，并给出系统的诊断证据支撑。
2. **深入的两维诊断分析**：论文先通过精心设计的诊断实验（Lean 形式的装备侧分析、TableQA 的参数侧 API 重命名分析）揭示了两类方法的本质瓶颈，方法论有坚实的实证基础，而非空泛断言。
3. **框架设计系统且可操作**：任务感知路由 + 阶段感知调度 + 双模态知识优化三个组件形成了完整的决策闭环（何时走哪条

（续上）通道、何时从装备侧切换到参数侧、知识该驻留在哪一侧），每个组件都有明确的输入输出和可验证的设计逻辑，具备工程可落地性。

4. **提出“知识易变性”这一关键判据**：论文将知识按 volatility 分层（易变/稳定/策略性），并配合抗背诵奖励和记忆释放机制，从“存哪里”的角度回答了知识管理问题，具有启发性和一定普适性。
5. **实验设计有针对性**：在仿真环境（TableQA 的 API 重命名）与真实环境（Lean 定理证明）中分别制造了“装备侧失效”和“参数侧失效”的对照场景，验证了双通道均存在盲区这一核心假设。
6. **性能-成本双重视角**：COVE 并非单纯追求精度，而是将训练 token 成本纳入评价框架，体现了对实际部署经济性的关注，增进了结论的现实意义。

### 8. 潜在缺点与局限性（更深入的分析）

1. **基础模型单一，规模与架构泛化性存疑**：所有主实验均基于 Qwen3-8B，未在更大规模模型（如 70B+）或其他模型家族（如 LLaMA 系、Mistral 系）上验证。由于不同基础模型在指令遵循、上下文利用、可塑性方面差异显著，COVE 的路由决策与记忆释放机制在更强或更弱的模型上是否依然成立，目前无法确认。
2. **路由器的可靠性与评估难题**：
   - 路由器本身是一个 LLM（Qwen3-8B / GPT-4o-mini / DeepSeek-v3.2），其决策质量直接影响系统整体表现，但论文未对路由器在各类任务上的决策准确率做系统评估，而仅报告了三个路由器之间 95% 的一致性。
   - 35% 的实例被路由到 hybrid 通道，但论文称某些方法在 Hybrid 子集上的表现可能被高估，原因是对该子集的构建依赖路由器自身分类，存在循环论证风险。
3. **对“反馈”质量与形式的依赖**：COVE 依赖环境返回的结构化反馈（奖励、评估器诊断消息等）。在现实中，许多任务无法获得这种细粒度的反馈信号（例如开放性写作、设计类任务），此时路由器的输入将退化为仅有任务描述，其决策质量可能大幅下降。论文未讨论反馈信号缺失或弱监督情形下的退化表现。
4. **训练目标对基线方法复现存在简化偏差**：论文将 Self-Challenging 的 RL 目标简化为等价于 rejection fine-tuning 的 token 核算，这可能导致对该基线能力的低估或高估；同时，由于未报告随机种子与方差，主结果中 COVE 相对基线的优势（尤其是部分任务差距较小的情况）的统计显著性无法判断。
5. **超参数敏感性未充分探讨**：记忆易变标签的初始标注方式、反复修订的判定次数、反背诵惩罚系数 λ、Plateau 窗口 w 与阈值 ε、数据充分性阈值 N、记忆释放的 A/B 评估阈值等一系列超参数，论文均以单一取值呈现，未做敏感性分析。这些超参数在不同任务或不同基础模型上可能产生显著波动。
6. **路由实验的 token 核算误差**：路由消融中的 token 成本是按固定每实例 14100 tokens 估算的，未区分不同路由路径的实际上下文注入长度（如 hybrid 路径可能同时注入两类知识），成本比较存在一定偏差；此外，路由器本身的推理 token 成本未计入整体开销。
7. **任务覆盖的局限性**：虽然覆盖了五类任务，但全部属于“可自动评估、能获得结构化反馈”的领域。对多轮交互、长周期规划、多智能体协作等更贴近真实智能体应用的场景，COVE 的通道协调逻辑能否直接迁移仍未验证。
8. **“记忆释放”可能带来隐藏风险**：论文的 A/B 评估只比较单次检索上下文中包含或不包含某条记忆的性能变化，但忽略了记忆间的交互效应（多条记忆的组合价值）、释放后模型在非分布任务上使用内化知识的泛化能力，以及释放后的知识更新困难（一旦内化，修改成本高于外部编辑）。

### 9. 个人评价与批判性思考

- **理论贡献的实质**：COVE 的价值主要不在于提出了全新的学习算法，而在于**将“在外部记忆与参数更新之间取舍”的隐式工程直觉，系统化为可显式决策、可调度、可验证的框架**。它将经验积累从“被动接收”改造为“主动路由”，这一视角转换具有方法论层面的一般意义。
- **“通道”隐喻的边界**：论文将装备侧与参数侧比喻为两个通道，但二者的本质并不对称——装备侧即时可检索、可用性不变形；参数侧却会改变后续所有行为。因此，路由决策本质上不对称：把知识放到参数侧的风险远大于放到装备侧。COVE 虽通过“易变知识永不内化”和“记忆释放”缓解了这一点，但其路由决策（parametric_candidate）并没有显式建模这种不对称性带来的风险评估，值得进一步探讨。
- **关于“知识易变性”的可操作性**：频发修订作为 volatile 的代理信号具有一定合理性，但也存在风险——某些修订可能是同样的错误反复出现（而非外部状态变化），在这种情况下提升为 volatile 会掩盖模型能力缺陷。一个更完善的机制应区分“环境驱动的修订”与“能力驱动的修订”。
- **路由器的成本悖论**：路由决策本身也消耗推理 token，且路由器的能力越强（如 GPT-4o-mini），外部依赖越重，这与智能体自主进化的目标存在细微矛盾。COVE 用小型模型做路由骨干的选择是务实的，但小型模型在复杂任务上的路由精度上限仍未探究。
- **对未来研究的启示**：COVE 为“元学习层面的智能体架构设计”提供了范式——即不直接优化任务的奖励，而是优化“如何学习”的策略。朝着这个方向，自然延伸的问题包括：路由策略是否可以自身通过 RL 端到端训练？记忆的易变标签是否可以随模型能力的提升而动态升级？参数内化后若环境回退，是否可以提取并反向输出到装备侧？

### 10. 总结

COVE 是一篇问题意识明确、框架设计完整、实验逻辑清晰的论文。它以“知识易变性”为主线，将大语言模型智能体的自我进化重新定义为**装备通道与参数通道的协同决策问题**，并提出了任务感知路由、阶段感知调度和双模态知识优化三大组件，从“何时走哪条通道、何时切换、知识放哪里”三个维度给出了可操作的答案。实验证明，这种协调相比任一单通道或盲目双通道，在性能和训练成本之间实现了更优的平衡。论文的局限同样明显：单一基础模型、对结构化反馈的依赖、路由器评估方法欠完备以及超参数敏感性未展开，使得其结论的普适性和统计稳健性有待后续工作加强。总体而言，COVE 是对 LLM 智能体持续学习研究的一次有价值的系统化尝试，其“通道协调 + 易变性感知”的思想有望在更大规模模型、更丰富任务类型和更长生命周期部署环境中得到进一步检验和发展。
